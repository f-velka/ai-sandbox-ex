# ホスト直接実行のための管理設定

コンテナを使えない環境では、実行環境の外側から境界を作れない。
この提供物は、AI エージェント製品の**管理設定**（利用者設定や起動時指定より優先され、エージェントから変更できない配置に置くファイル）で、製品の内蔵サンドボックスと外部機能の制限を強制する。

- [claude-code/](claude-code/README.md)：Claude Code の管理設定（macOS、Linux、WSL2）
- [codex/](codex/README.md)：Codex の管理要件（macOS、Linux、Windows）

## 保証すること

後述の施錠を行った場合に、次が成り立つ。

- 管理設定は利用者設定と起動時指定より優先され、エージェントの権限では変更できない。
- 内蔵サンドボックスが常に有効になり、サンドボックスを通らない実行方式を選べない。
- Web 検索や MCP サーバーなどの外部機能は、管理者が明示的に許可したものに限られる。
- ファイルと外向き通信の制限は、製品の内蔵サンドボックスが定める範囲で適用される。

## 保証しないこと

強制は製品のプロセス内の実装に依存する。
このため、製品の欠陥や未知の迂回はこの提供物では防げない。
実行環境サンドボックス（[.devcontainer/](../docs/design.md)）が持つ「経路がそもそも存在しない」という構造的な既定拒否は、ここにはない。
この差が、二つの提供物の保証の強さの差である。

制限の意味（何が作業領域か、どの通信を許すか）は製品の版が定義する。
また、監査基盤は含まない。

## 実行環境サンドボックスとの関係

二つの提供物は独立して使える。
サンドボックス内にも製品の管理設定が組み込まれているが、あちらは外側の境界を通らない経路（Web 検索など）を塞ぐ部品であり、この提供物の設定は単独で境界を担うため内容が異なる（サンドボックス強制のキーを含む）。
併用した場合、この設定は外側の境界に対する防御の重ね掛けとして働く。

## 施錠

管理設定は、配置しただけでは保証にならない。
エージェントの権限で書き換えられるなら、それは制限ではなく初期値である。

配置したファイルと親ディレクトリの所有者を root（Windows では管理者）にし、エージェントを実行するユーザーの書き込み権を外す。
確認は、エージェントを実行するユーザーで書き込み可否を調べる。

```console
$ test -w /etc/codex/requirements.toml && echo writable || echo locked
locked
$ test -w /etc/codex && echo writable || echo locked
locked
```

Windows では、Codex を実行するユーザーでファイルの上書きを試み、拒否されることを確認する。

## 版数の規律

設定キーの意味と強制範囲は、製品の版で変わり得る。
各製品の README は、設定を確認した対応バージョンを明記する。
版を上げるときは、公式文書で各キーが同じ意味で強制されることを確認してから、設定と対応バージョンの記載を更新する。
